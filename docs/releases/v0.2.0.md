# Team Agent v0.2.0 — The multiplayer lobby for coding agents

![Team Agent social preview](https://raw.githubusercontent.com/boxzeemon-beep/team-agent/v0.2.0/docs/assets/social-preview.png)

Team Agent lets a browser-only teammate borrow another member's local Codex for
one shared project. The requester chooses the Agent, follows its work live, and
reviews the response, diff, tests, and commit. Codex and Git credentials stay on
the Agent owner's computer.

## Try the lobby without credentials

The new Demo Mode opens a populated tactical lobby and simulates the complete
browser workflow without launching Codex or touching a Git repository:

```bash
docker run --rm -p 127.0.0.1:4310:4310 -e TEAM_AGENT_DEMO_MODE=1 \
  ghcr.io/boxzeemon-beep/team-agent:0.2.0
```

Open <http://127.0.0.1:4310>, select the online Demo Agent, and submit a task.
The task moves through `queued → running → completed` and returns an explicitly
labelled simulated result, diff, test output, and commit identifier.
Runner pairing and deployment-management endpoints are disabled, and the
example binds the playground to the local loopback interface.

From a source checkout, use `pnpm install && pnpm demo:playground`, then open
<http://127.0.0.1:4311>. The existing `pnpm demo:smoke` command remains the
protocol-level proof that exercises Coordinator, SQLite, WebSocket Runner,
local Git, tests, commit, and push.

## What's new

### A tactical collaboration lobby

- **Operation Mode** shows the real project, shared branch, and task count.
- **Agent Squad** makes every contributed Codex directly selectable.
- **Operation Brief** accepts the task from the lobby instead of hiding it in a
  separate workflow.
- The main action truthfully changes between **Start task**, **Join task queue**,
  and **Wait for Agent**.
- Mission log and results retain requester, actual Agent, owner, conversation,
  response, diff, tests, and commit.
- Desktop, tablet, and mobile layouts share the same functional workflow.

### Credential-free Demo Mode

Set `TEAM_AGENT_DEMO_MODE=1` to start an isolated playground with four clearly
labelled Demo Agents and representative running, completed, waiting, and
attention states. Demo tasks are simulated inside Coordinator and never call
Codex, read a repository, create a real commit, or push Git changes.

### Multi-architecture container

The Coordinator image now publishes for both `linux/amd64` and `linux/arm64`.
Docker selects the matching image for Intel/AMD Linux hosts, Apple silicon, and
other ARM64 environments.

## UI labels map to real system state

| Lobby label | Coordinator / Runner meaning | New task behavior |
| --- | --- | --- |
| Ready | Agent is online and idle | Starts after the project lock is acquired |
| Busy | Agent is running a task | Joins that Agent's queue |
| Offline | Runner is disconnected | Waits for the selected Agent |
| Paused | Owner paused sharing | Requester selects another Agent or waits |
| Waiting for owner | Local Codex approval is required | Owner handles it on the Runner computer |
| Needs attention | Test, commit, or push needs review | Team inspects the recorded result |

The lobby does not invent currency, levels, rankings, or success rates.

## Deploy for a real team

```bash
git clone --branch v0.2.0 https://github.com/boxzeemon-beep/team-agent.git
cd team-agent
cp .env.example .env
docker compose up -d
```

Claim the one-time administrator invite from `docker compose logs coordinator`,
configure the Git repository and shared branch, invite teammates, then generate
a one-time Runner pairing command from the project page.

## Upgrade from v0.1.x

1. Back up the Coordinator SQLite data directory and deployment configuration.
2. Pull tag `v0.2.0` or image `ghcr.io/boxzeemon-beep/team-agent:0.2.0`.
3. Restart Coordinator with the existing data volume.
4. Update each Runner while keeping its existing data directory.
5. Run one bounded test task before resuming team work.

## Security boundary and current limits

- Browser sessions, invitations, and Runner credentials are stored server-side
  as SHA-256 digests; pairing tokens are short-lived and single-use.
- Runner uses the owner's existing Codex and Git permissions. Only share Agents
  with teammates who should access the configured project.
- Native Codex approvals stay on the Agent owner's computer.
- One Coordinator currently manages one project and one shared working branch.
- Code tasks are serialized by one project-wide execution lock.
- Codex is the first supported Agent; additional adapters are on the roadmap.

Read [SECURITY.md](https://github.com/boxzeemon-beep/team-agent/blob/v0.2.0/SECURITY.md)
and the [deployment checklist](https://github.com/boxzeemon-beep/team-agent/blob/v0.2.0/docs/security.md)
before a real team deployment.
