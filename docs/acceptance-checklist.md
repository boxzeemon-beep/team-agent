# 内测验收清单

这份清单对应第一阶段唯一目标：团队成员明确选择并借用另一位成员共享的 Codex，在同一份项目上下文和 `internal-alpha` 代码状态上串行推进开发任务。

## 参与者

- [ ] 邀请 3–5 位真实成员
- [ ] 至少 2 位成员完成 Runner 配对并共享 Codex
- [ ] 至少 2 位成员只使用网页，不运行 Runner

## 核心流程

- [ ] 网页成员可看到每个 Agent 的名称、所有者和在线状态
- [ ] 零 Agent 成员可明确选择不同成员的 Agent 创建任务
- [ ] 完成至少 10 个真实开发任务
- [ ] 至少发生 3 次跨 Agent 所有者切换
- [ ] 新 Agent 收到上次参与后新增的项目讨论、前序结果和 commit
- [ ] 每个完成任务都展示发起人、实际 Agent、所有者、对话、diff、测试结果和 commit

## 队列与恢复

- [ ] 多人同时提交任务时，任意时刻只有一个任务处于 `running` 或 `waiting_for_owner`
- [ ] 选中的 Agent 离线时，任务保持等待且不阻塞其他在线 Agent 的任务
- [ ] 等待中的任务可由发起人重新选择 Agent
- [ ] Agent 恢复连接后，目标仍为该 Agent 的等待任务可继续执行
- [ ] 协调服务重启后，成员、Agent、任务、消息和上下文游标仍存在
- [ ] Runner 重启后，配对身份、受管副本和本地 Codex Thread 仍存在

## Git 与人工处置

- [ ] 每个正常完成的代码任务生成 commit 并推送到 `internal-alpha`
- [ ] 测试失败会进入 `needs_attention`，并保留测试输出与当前 diff
- [ ] 推送失败会进入 `needs_attention`，并保留本地 commit SHA 与诊断信息
- [ ] Agent 所有者可在本机处理 Codex 原生审批，网页同步显示 `waiting_for_owner`
- [ ] 正式分支只经过人工审查后合并

## 紧急释放

- [ ] 普通成员看不到紧急释放入口，直接请求接口得到 403
- [ ] Agent 在线时管理员的紧急释放请求保持原任务和全局锁
- [ ] 离线活动任务经管理员确认后进入 `needs_attention`，原 assignment 保留，Agent 进入 `paused`
- [ ] 任务对话记录紧急释放系统消息，队列中的下一个在线任务随后开始
- [ ] 操作前已确认 Agent 所有者电脑上的 Runner 进程停止，恢复共享前已检查其受管工作区

## 使用意愿

- [ ] 至少 2 位零 Agent 成员在一周内主动使用第二次
- [ ] 记录每次放弃任务的原因和完成任务耗时，作为内测后的产品判断依据
